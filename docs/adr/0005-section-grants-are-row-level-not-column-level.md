# Section grants restrict rows, not columns

Adding the Admissions section grant (write access to `courses`/`scholarships` for non-full-admin users like Parita) raised the question of whether a grant-holder should be limited to specific columns (e.g. only `intake`, `fees_per_semester`, `duration`, `eligibility`, `brochure_file_url` on `courses`), since the admin UI for that section only exposes those fields. We decided RLS enforces access at the row level only — a grant-holder's writes are gated by scope/section membership, not by which columns changed — matching the existing `sports_secretary` precedent (full row write on `sports`/`achievements`, no column lock). The admin UI hiding other fields is a convenience, not a security boundary; a grant-holder could in principle write any column via a direct API call. We accepted this because building column-level enforcement (a trigger that must distinguish full-admin writers from section-scoped ones) adds real complexity for a theoretical devtools-level risk against trusted staff, not a practical one. Any future section grant should assume the same: if a section genuinely needs column-level restriction, that's a deliberate deviation from this precedent and should get its own ADR.
