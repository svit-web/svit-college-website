# Tile destinations resolve live, not as a stored URL

Campus life tiles needed a way to link to a real Facility, Student Club or Event. The simple option was to keep the existing free-text `link_href` and just add a picker in admin that auto-fills it with that Entry's current URL — no schema change, minimal work. We rejected this because it only fixes the link at the moment an admin picks it: if the Entry is later renamed, re-categorized (a Facility's URL includes its category), or its Detail page is toggled off, the snapshotted URL goes stale exactly like today's hand-typed links do, defeating the point of linking to "the actual real facility" instead of a string. Instead, a tile stores `link_entity_type` + `link_entity_id` and the public page resolves the live Entry's URL (and Detail-page availability) at render time, via the Entry's own id — the Campus life tile's title/eyebrow/photo stay independently editable and are never overwritten by this. The cost is a small schema addition and a per-type resolver (reusing `getFacilityBySlug`/`getStudentClubBySlug`/`getEventBySlug` by id instead of slug); we accepted that cost because a broken or misleading link on a public marketing page is worse than the extra resolution step, and the Entry model already treats Detail-page availability as dynamic (`has_detail_page`), so a "resolve now" tile destination is consistent with how Entries already work everywhere else.
